#b  SOC L1 Alert Reporting- TryHackMe

## Objective
Learn how to properly report, escalate, and communicate high-risk security alerts in a SOC environment.

## Skills Learned
- Understand the need for SOC alert reporting and escalation
- Learn how to write alert comments or case reports properly
- Explore escalation methods and communication best practices
- Apply the knowledge to triage alerts in a simulated environment
- Feel more confident in SOC Simulator and during SAL1 certification
  
## Tools Used
- TryHackMe SOC Simulator
- SIEM alert data
- Alert investigation and reporting tools
- Security event and process information

## Key Steps

1. Reviewed security alerts and identified important indicators such as suspicious processes, authentication failures, attachments, and command activity.
2. Examined alert details including timestamps, affected hosts, users, processes, and security checks.
3. Determined whether the activity appeared legitimate or suspicious based on the available evidence.
4. Wrote concise investigation comments describing what occurred and why the activity was suspicious.
5. Identified alerts that required escalation or additional investigation.
6. Practiced communicating findings clearly so another SOC analyst could continue the investigation.

## What I Learned
I learned how and when to escalate SIEM reports and how to write clear reports when escalating an alert. I also learned to include the 5 W's and relevant information such as affected users, command activity, and failed security checks when writing the report. This room helped me to understand how to efficiently communicate as a SOC analyst and how to document alerts so they can be investigated efficiently.
